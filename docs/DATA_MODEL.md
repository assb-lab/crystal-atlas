# データモデル

`src/data/atlas.ts` が各データモジュールを統合し、UI・JSON書き出し・テスト・単一HTMLビルドに同じデータを供給します。内容は単一HTML v1.0から移植したものです。各フィールドの型は `src/types.ts` で定義し、型チェックで不正な項目を検出します。

## 構造ノード: `structures.ts`

必須項目は `id`、`name`、`formula`、`family`、`sg`、`desc`、`packing`、`coord`、`link`、`refs`、`x`、`y` です。

| 項目                       | 意味                                                      |
| -------------------------- | --------------------------------------------------------- |
| `id`                       | 一意な内部ID。関係・ルート・模型から参照                  |
| `family`                   | `families.ts` にあるファミリーID                          |
| `sg`                       | 出典に沿った空間群・対称性の表示文字列                    |
| `packing`, `coord`, `link` | 骨格、配位環境、多面体・部分構造の連結                    |
| `occ`                      | 任意。全T孔・全O孔をそれぞれ分母にした `[T, O]` 占有率    |
| `host`                     | `occ` の基準となる充填粒子。`occ` を設定した場合に必要    |
| `refs`                     | 参照箇所の配列。例: `{s: 'M06', p: 161, sec: 'Fig.15.3'}` |
| `x`, `y`                   | ファミリー内のグラフ座標                                  |
| `model`                    | 任意。`src/lib/viewer.ts` が生成できる理想模型のID        |
| `aliases`, `note`          | 任意。検索別名、注意点                                    |

## 関係: `relationships.ts`

必須項目は `id`、`a`、`b`、`kind`、`label`、`desc`、`refs` です。`a` と `b` は構造IDです。

`kind` は `symmetry`、`occupation`、`ordering`、`distortion`、`stacking`、`analogy`、`antitype` のいずれかです。ラベル・配色・説明は `presets.ts` の `KINDS` にあります。

群–部分群として出典確認した関係には `strict: true` を付け、`index`、`basis`、`split` に部分群の種類・指数、基底／原点／セル、サイト対応を記載します。未転記・未検証の詳細は説明中で明示してください。単に空間群が似ているという理由で `strict` を設定しないでください。

`undirected: true` は方向を主張しない関係です。比較画面の接続経路探索は、表示上の矢印の向きによらず無向グラフとして動作します。

## 出典: `sources.ts`

各参照の `s` が出典IDを指します。PDFページ番号は **印刷ページ `p` + 出典の `offset`** で、いずれも1始まりの表示です。公開資料には `url`、手元で関連付ける資料には `filename` を指定します。

## 更新時

構造や関係を追加したら、一意なID、既存の接続先、参照箇所、骨格の基準を確認し、`pnpm check` と `pnpm test` を実行してください。初期データとのハッシュ一致テストと件数テストは、意図的なデータ更新時に変更内容を確認した上で更新します。ファミリー内の配置は自動レイアウトではなく手動座標です。全体地図のタイル配置は `src/lib/graph.ts` の `OVERVIEW.order` で決めます（ファミリーを追加した場合は末尾に並びます）。

ビルドスクリプトはこのアプリの名前付きES Modulesに限定した処理です。新たなimport構文や同名のトップレベル変数を導入した際は、単一HTMLビルドの互換性も確認してください。
