# 基本充填からの構造アトラス

## 目的と読み方

主画面を、独立した `family` / `collection` / `flow` 選択から、共通の構造階層へ変更する。出発点は **bcc / ccp・fcc / hcp**。単純立方、単純六方、追加の骨格も明示する。hcpは六方ブラベー格子hPに2原子の基底を置いた配列であり、14ブラベー格子の一つという意味ではない。

基本配列から、空隙占有・サイトの規則化・欠損・歪み・積層を経て構造型をたどり、具体組成・相を末端に置く。**縦位置は選択した主経路の深さであり、対称性の高さ、原子数、安定性、反応の進行順ではない。** 全てをBärnighausen treeと呼ばない。

一つの結晶構造には複数の記述が可能なので、表示上の主経路は一つに選ぶ。原資料の別経路は削除せず、紫のオーバーレイと詳細欄から参照できる。構造原理の相互関係を、唯一の生物学的な系統樹のように扱わない。

## 三つの接続と四つのノード

| 主接続 | 意味 | 例 |
| --- | --- | --- |
| `derivation` 実線 | 構造記述上の操作 | bcc → B2、ccp → 蛍石、ルチル → トリルチル |
| `instance` 点線 | 共通構造を実現する具体組成・相 | パイロクロア → Y₂Ti₂O₇ |
| `organizes` 破線 | 分岐の案内・比較 | ペロブスカイト → Bサイト規則化 |

ノードは `packing`（基本配列）、`prototype`（構造型・共通模型）、`material`（具体組成・相）、`guide`（整理用の分岐）に分ける。構造型の名称に代表化合物の組成が含まれる場合もあるため、化学式の有無だけでは型と実物質を区別しない。

整理用の分岐は結晶構造や測定された相ではない。共通模型にも実測CIFを捏造しない。既存の座標データは元の具体的な構造カードで表示する。

## 主要な修正

- `ccp → 蛍石 → 欠陥蛍石の平均模型 → パイロクロア → Y₂Ti₂O₇ / La₂Zr₂O₇ / Cd₂Re₂O₇`。具体例を無向の類似線だけで扱わない。平均模型から秩序型への記述は編集上の主経路であり、特定物質の温度相転移ではない。
- `ccp → A/X=1:3の混合ccp → ペロブスカイト`。Xだけのccpではない。Bサイト1:1と1:2を兄弟として配置し、Ba₂MgWO₆をBa₃SrTa₂O₉の親にしない。
- RP系列のn=1/2/3、AO₃層の2H/4H/6H/9Rを、周期の長い順の世代にしない。
- ルチルは岡本のB2サイトへの構造ブロック置換という記述を主経路に採用する。hcp→NiAs→CaCl₂→ルチルという別記述は原資料の関係として残す。ルチルを厳密なhcp部分群とはしない。
- β-MnO₂、CaCl₂型、トリルチル、シアー系列、トンネル比較をルチルの先で探索できる。CdCl₂はccp/岩塩側、Cu₃NはReO₃の反型側に置く。
- 同じ組成の相転移、別物質間の類似、部分格子の共有を、無差別に上下の順位へ変換しない。

## 画面

上部に基本配列、左に一つの展開式ナビゲーション、中央に主階層、右に構造と接続の詳細を置く。構造検索は新しい共通模型も検索する。既存の全件検索、比較、投影方向、サイト表示、構造ラボ、出典参照は保持する。

どの枝を開いても、その基本配列までの祖先を残す。大きい枝は折り畳めるが、表示中の枝に至る祖先は折り畳みによって消えない。初期表示は主要な枝を畳み、読める倍率で選択付近を表示する。「全体に合わせる」は俯瞰用。

「岡本の図」「文献」「横断テーマ」は同じ地図に対する強調表示。強調だけで親子・座標は変更しない。「該当項目と祖先を表示」を明示的に選んだ時だけ範囲を変更する。GlazerやDelmasなどの既存の分類表は参照表として残す。

## データの保全・根拠の境界

既存の220構造・283関係・座標・出典は変更しない。`packing-plan.ts` はその上に置く編集上の投影定義で、45個の案内・共通模型を追加する。これらを新たに測定された45結晶として数えない。元データのJSON出力は引き続き元データだけを出力する。

各主接続は元の関係ID、または元構造の説明・参照箇所を持つ。根拠欄に引用があることと、その引用が本アトラスの編集上の階層全体を証明することは別である。原資料の記述を確認するリンクを残す。群–部分群の確認済みフラグは、端点・方向・元関係が一致する場合だけ引き継ぐ。元の無向関係を、文献図を選んだだけで有向に変換しない。

BaAl₄、CeMg₂Si₂、ガーネットなど、今回の投影で基本充填への根拠を確定しなかったものは「追加の骨格・導出未確定」に置く。**bcc/ccp/hcpから導けないと断定しているのではなく、今回の主経路を保留している。** この入口への線は分類案内であって導出ではない。今後追加される未配置レコードも同様に警告付きで見える状態にする。

## ソース

- `src/data/packing-plan.ts`: ノード区分、共通模型、主経路、根拠の対応。
- `src/lib/packing.ts`: 構築時検証、祖先・子孫、強調、範囲抽出、木の配置、別経路。
- `src/components/explore/PackingExplorer.tsx`: 統一ナビゲーションと既存のモデル・比較機能との接続。
- `src/components/explore/PackingMap.tsx`: 主階層のSVG描画。別経路は順位計算に参加しない。
- `src/styles/packing.css`: 新しい探索画面のみのスタイル。
- `tests/unit/packing.test.ts`: データの保全・到達性・具体例・配置・根拠を検証。
- `tests/e2e/smoke.spec.ts`: 新ナビゲーションに移行した配信版／単一HTMLの回帰テスト。

`window.packingDiagnostics()` は新しい画面の読み取り専用診断。既存の `atlasDiagnostics()` は旧投影の診断も含むため、新画面の件数確認には使用しない。

## 検証

通常の開発環境では `pnpm check`、`pnpm test`、`pnpm build`、`pnpm e2e`（または `pnpm verify`）を実行する。

この変更の作成環境ではNode.js 26・pnpm 12の依存解決ができなかったため、クリーンなViteビルドとリポジトリ全体のverifyは未確認。純粋なデータ処理は既存単一HTMLから取得した実データで17項目を実行。UIは新TS/TSXをトランスパイルし、ユーザー提供の既存React単一HTMLの実ランタイムへ組み込んで、Chromiumで検索・階層・比較・単位胞・モバイル等22項目を検証した。これはクリーンビルド検証の代替ではない。PRはDraftとして提出し、通常環境でのverifyと第三者レビューをマージ前の確認事項とする。
